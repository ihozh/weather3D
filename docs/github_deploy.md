# GitHub → Oracle VPS Deployment Walkthrough

End-to-end path: **laptop → `git push` → GitHub repo → VPS `git pull` + auto-reload**.

Hourly HRRR data is generated by the VPS itself via `scripts/build-latest-weather.sh`; it is **never committed to git**.

---

## Step 0: Audit what gets pushed

The current `.gitignore` already excludes:

- `.venv/`, `__pycache__/`, `*.pyc`, `.DS_Store`
- `*.mp4` (screen recordings)
- `NationalCSB_2018-2025_rev23/`, `2025_30m_cdls/` (raw GB-scale source data)
- `data/csb-mesonet.geojson` + `data/csb-mesonet-simplified.geojson` (CSB intermediates)
- `data/weather/hrrr/grib/`, `data/weather/hrrr/[cycle]/`, `*.npz`, processed HRRR outputs
- `dist/` (esbuild artifacts)
- `node_modules/`

Large files that DO go into the repo:

| File | Size |
|---|---|
| `data/csb-mesonet-crops.geojson` | 16 MB (compacted) |
| `data/water/usa-detailed-water-bodies.geojson` | 11 MB |

GitHub has a hard 100 MB per-file limit — both are well under. The 16 MB file will trigger a warning ("> 10 MB") but pushes fine. If you'll frequently rebuild these, consider Git LFS:

```bash
git lfs install
git lfs track "data/csb-mesonet-crops.geojson"
git lfs track "data/water/usa-detailed-water-bodies.geojson"
git add .gitattributes
```

LFS is optional — git can absorb 16 MB files, history just grows over time.

## Step 2: Clone on the VPS

### 2a. Public repository (simplest)

```bash
sudo mkdir -p /opt/weather3d
sudo chown "$USER:$USER" /opt/weather3d
git clone https://github.com/USER/weather3d.git /opt/weather3d
cd /opt/weather3d
```

### 2b. Private repository — use a deploy key

Generate a dedicated SSH key on the VPS:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/weather3d-deploy -C "weather3d@oracle-vps" -N ''
cat ~/.ssh/weather3d-deploy.pub
```

Paste the `.pub` content into the GitHub repo's **Settings → Deploy keys → Add deploy key** (read-only is fine).

Configure SSH on the VPS to use that key:

```bash
cat >> ~/.ssh/config <<'EOF'
Host github-weather3d
  HostName github.com
  User git
  IdentityFile ~/.ssh/weather3d-deploy
  IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config

git clone git@github-weather3d:USER/weather3d.git /opt/weather3d
cd /opt/weather3d
```

## Step 3: First-time install and bring-up

```bash
cd /opt/weather3d
sudo apt-get update
sudo apt-get install -y python3 python3-venv python3-pip nginx libeccodes0

python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements-hrrr.txt

# Verify HRRR fetch works end-to-end
./scripts/build-latest-weather.sh

# Install the hourly systemd timer
sudo cp deploy/systemd/weather3d-hrrr.service /etc/systemd/system/
sudo cp deploy/systemd/weather3d-hrrr.timer   /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now weather3d-hrrr.timer

# Install nginx config
sudo cp deploy/nginx/weather3d.conf /etc/nginx/sites-available/weather3d
sudo ln -sf /etc/nginx/sites-available/weather3d /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

# Open OS firewall (Oracle Cloud Security List still needs separate config!)
sudo ufw allow 80/tcp && sudo ufw allow 443/tcp

# Visit http://VPS_IP/ to verify
```

## Step 4: Updates — pick one

### Option A: manual `git pull` (recommended starter)

After every local push, SSH to the VPS:

```bash
cd /opt/weather3d
./scripts/deploy.sh
```

`deploy.sh` does:
- `git fetch + pull --ff-only`
- runs `pip install` only if `requirements-hrrr.txt` changed
- restarts the systemd timer
- runs `nginx -t && systemctl reload nginx`
- typically < 5 seconds when no deps changed

### Option B: cron polls every minute

```bash
crontab -e
# Add:
* * * * * cd /opt/weather3d && ./scripts/deploy.sh > /tmp/weather3d-deploy.log 2>&1
```

At most 1-minute delay after push. No GitHub-side configuration needed.

### Option C: GitHub Actions → SSH (cleanest, ~30s after push)

Create `.github/workflows/deploy.yml`:

```yaml
name: Deploy to VPS
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: SSH deploy
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.VPS_HOST }}
          username: ${{ secrets.VPS_USER }}
          key: ${{ secrets.VPS_SSH_KEY }}
          script: |
            cd /opt/weather3d
            ./scripts/deploy.sh
```

In the GitHub repo **Settings → Secrets → Actions** add:
- `VPS_HOST`: Oracle VPS public IP / domain
- `VPS_USER`: `ubuntu` or `opc`
- `VPS_SSH_KEY`: an SSH private key whose pub is in the VPS's `~/.ssh/authorized_keys`. Generate a dedicated one:
  ```bash
  ssh-keygen -t ed25519 -f gha-deploy -N ''
  # add gha-deploy.pub to VPS ~/.ssh/authorized_keys
  # paste contents of gha-deploy (the private key) into the secret
  ```

Push to `main` triggers the workflow, which pulls on the VPS within ~30s.

## Common pitfalls

| Symptom | Cause | Fix |
|---|---|---|
| `git push` fails with "file > 100 MB" | wrong file slipped past .gitignore | `git rm --cached <file>` and re-commit |
| VPS `git pull` says "rebase needed" | someone edited code on the VPS directly | Don't edit on VPS — commit locally and push back |
| `systemctl reload nginx` permission error | `deploy.sh` uses sudo but current user has no NOPASSWD | `sudo visudo`: `USER ALL=(ALL) NOPASSWD: /bin/systemctl restart weather3d-hrrr.timer, /bin/systemctl reload nginx, /usr/sbin/nginx -t` |
| Frontend gets CORS errors on data | nginx not reloaded or config not installed | `nginx -t && systemctl reload nginx`; verify `/etc/nginx/sites-enabled/weather3d` exists |
| HRRR fetch fails | NOAA hasn't published the cycle yet / transient network | Timer is hourly with 5-min jitter, next slot will retry |

## Security notes

- VPS owns `/opt/weather3d` as a normal user (not root)
- nginx runs as `nginx`/`www-data` (default)
- Restrict NOPASSWD sudo to the precise commands in `deploy.sh`
- HTTPS via `certbot --nginx -d <domain>`
- Private repos use a read-only deploy key
- Never commit `.venv/` (already ignored)
